## What the scan says about engine lineage

- **The M3D/Spool/Decomp core is remarkably stable from THPS1-final (Sept 1999)
  through SM2:EE Rev1 (Sept 2001)**: `DecompressStream`, `Spool_FindAnim`,
  `Spool_GetModel`, `M3dUtils_InterpolateVectors`, `M3dUtils_InBetween`,
  `M3dUtils_AnglesFromMatrix` all score 0.92–1.000 in every one of those
  builds. Notably `DecompressStream` (the v2 codec) already exists
  **byte-identical in THPS1 final**.
- **Game-side playback (`RunAnim`/`CycleAnim`/`UpdateFrame`/`SetAnimOrder`/
  `CalculateAnimOrder`/`PatchAnimationOrder`) only matches within the THPS
  line** (THPS1-final ≈ THPS2). Spider-Man/SM2:EE rewrote or heavily diverged
  that layer — expected, different game logic on the shared engine.
- **THPS1 proto (April 1999) is a different codebase generation**: only the
  Spool layer and the small math helpers carry over. Most anim functions need
  fresh RE there, anchored from the few confirmed matches below.
- **Apocalypse (1998) is a cold target**: nothing matches except
  `M3dUtils_AnglesFromMatrix` at 0.837. Different compiler era and/or heavy
  source drift. `DecompressStream` genuinely absent (v1-only game).

## What the multitool needs answered, in priority order

1. **Hawk arms (THPS1 proto)** — proto hawk renders TWO overlapping arm
   surfaces (skin arm + sleeve arm in the same space); the game clearly draws
   only one. In the THPS2-proto contract, characters render exactly
   `ppModels[part]` 1:1 with pose remap by AnimOrder name — so either THPS1
   proto selects parts differently, or something at load strips/deselects one
   arm variant. Targets in `PSX.EXE`: whatever populates `ppModels` (its
   `M3dInit_ParsePSX` ancestor), its `RenderSuperItem` ancestor, and any
   `Spool_StripModel`/`Spool_GetReducedSkater` ancestor. Anchors above; the
   render loop should be findable from `M3d_BuildTransform` (0x80052E54)
   xrefs. The deliverable is the selection rule: given hawk.psx's duplicate
   arm meshes, which one draws and why.
2. **M3dInit_ParsePSX in your own project (0x8009392C)** — still unmatched,
   and now proven ~unchanged in THPS1 final (0.984). Matching it once closes
   three INFERRED gaps at once: the load-time draw-enable (our XOR-0x80), the
   NextLOD/zMax header packing, and ppModels population. Probably the single
   highest-value function left for the multitool.
3. **Apocalypse v1 tween call sites** — our interval=tweenFlag+1 tween
   expansion was derived from THPS2-proto call sites, but Apocalypse (the
   heaviest tween user) shares no matching code with the reference, and its
   `M3dUtils_InterpolateVectors` equivalent wasn't found by signature. Bruce
   renders coherently so the contract probably holds, but a spot-check of
   Apocalypse's tween expansion (find it via the AnglesFromMatrix anchor +
   1.12 fixed-point `<<12 / span` patterns) would confirm or refute.
4. **CycleAnim wrap-toward-frame-0 tween tail** (nice-to-have) — cycled clips
   should interpolate the last keyframe toward frame 0 rather than clamping;
   we currently always use the non-cycle clamp. Confirming the exact wrap
   arithmetic in CycleAnim/UpdateFrame would let us add it as an option.
