# Neversoft Multitool - AI Assistant Instructions

## Project Overview

.NET 10.0 application for extracting and converting assets from Neversoft game files (PS1, Dreamcast, Xbox, PC). Features WinUI 3 GUI (Windows) and cross-platform CLI. Ported from Python/PyQt6.

Supported formats:

- **PSX files**: Multi-purpose format containing textures + optional 3D mesh geometry. File naming conventions: `*_g.psx` = level geometry, `*_l.psx` = texture library (paired with `_g`), `*_o.psx` = level objects, no suffix = character/creature/item model. Textures: 4-bit/8-bit paletted (PS1), 16-bit PowerVR (twiddled, VQ, rectangle) — PS1, Dreamcast, Xbox. Meshes: → glTF (.glb) with vertex colors, normals, and texture references. **Format versions** (0x03, 0x04, 0x06) are unreliable — prototype builds may share a version ID but differ structurally; the only true-v6 builds are the Spider-Man DC/PC ports (THPS2 DC and THPS2X Xbox ship v4), v6-swept 2026-07-10 at 317 GLBs / 0 validator errors (v6 widens UVs to plane-separated u16/i16 pairs in a fixed /512 space — empirical, pinned by the BLACKCAT.PSX fixture). **ABR blend export**: semi-transparent faces (bit6) carry a 2-bit blend rate in flags bits 7-8 (decomp-verified face_flag_semantics.md) baked per-rate into textures: 0 = average → hue-preserving 50% alpha (62.5% of the corpus), 1 = additive → luminance-to-alpha (24.7%), 2 = subtractive → black+brightness alpha (10.1%), 3 = quarter additive (2.7%); rate is part of the material cache key. Survey: `tools/diagnostics/psx_abr_survey.py`. **Anim export**: tween-compressed clips expand in CycleAnim loop mode by default (final interval blends toward frame 0, decomp-verified cycle_anim_wrap.md); `--one-shot` restores the RunAnim clamp. Engine timeline: Apocalypse (1998) → THPS1 (1999) → Spider-Man (2000) → THPS2 (2000) → SM2:EE (2001)
- **PVR textures**: Standalone Dreamcast GBIX+PVRT textures (ARGB1555, RGB565, ARGB4444; twiddled, VQ, rectangle)
- **RLE/BMR bitmaps**: Neversoft's custom RLE compression — RGBA5551 (PS1) and BMP-wrapped 24-bit RGB (Dreamcast). The `rle` CLI + Bitmap Converter tab also convert standard `.bmp`/`.tga` (via ImageSharp, alpha preserved — `Core/Formats/Rle/BitmapFile.cs` facade)
- **WAD+HED archives**: Paired archive/index format used in Apocalypse, THPS series
- **PKR3 archives**: Compressed archive format used in Spider-Man PC
- **PRE archives**: Simple flat archive format used in THPS1 (PS1), THPS2 (PS1, Dreamcast). LZSS-compressed PRE v3 (0xABCD0003) also ships as **`.prd` (German)** / **`.prf` (French)** / `.prg` localized variants (THUG2, 316 files) — byte-identical to `.pre`, routed through `CompressedPreArchive` (THUG source `gs_file.cpp:52-63`, `p_filesys.cpp:130-158`). Localized variants extract to a full-name dir (`anims.prd/`) via `ArchiveNaming.GetExtractionStem` so they don't merge with the same-stem `.pre`/`.prx` sibling.
- **DDX archives**: Xbox texture archives containing DDS files (THPS2X)
- **QTex ZIP bundles**: THAW PC/GC texture-SOURCE archives (`<tex>.tex.zip.wpc` / `.zip.ngc` under `models/**`, 1,337 files). STORE-only PKZip holding the material's original authoring art (little-endian TIFF/PNG incl. `_n`/`_s` normal/specular maps) + a `debug.log` of `texturetool` build lines (EOCD comment "Generated by QTex"). The central directory is malformed (garbage extra fields; some files duplicate CDHs with the CRC in the compressed-size slot), so strict CD-based readers reject the whole corpus (Python zipfile 0/1,337) — `QZipArchive` walks the clean LOCAL file headers from offset 0 instead. STORE + DEFLATE supported; inner names are art-source names (no platform suffixing). CLI: `archive <x>.zip.wpc`; routed through `unpack`.
- **CUT cutscene libraries**: THUG/THUG2 `.cut`/`.cut.ps2`/`.cut.xbx` (215 files) — the engine's `CFileLibrary` format (THUG source `Sys/File/FileLibrary.{h,cpp}`): `{u32 version=1, i32 numFiles}` + a TOC of `{u32 offset, i32 size, u32 nameQbKey, u32 extQbKey}` + contiguous little-endian data blobs. Payloads keyed by extension checksum (from `Sk/Objects/cutscenedetails.cpp:3098-3200`, **NOT** pak-style `QbKey(".ext")` — map is hardcoded): 0x5AC14717 CIF · 0xEAB51346 SKA · 0x05CA1497 CAM · 0x2E4BF21B OBA · 0x2BBEA5C3 QB · 0xE7308C1F GEOM(PS2) · 0x0524FD4E MDL(Xbox) · 0xFD8697E1 SKIN · 0x1512808D TEX · 0xFFC529F4 CAS · 0x2CD4107D WGT · **0xEDD8D75F SKE** (=QbKey("ske"), THUG2) · **0x508AE2F2 CIF2** (THUG2 CIF replacement, layout unknown, dumped raw) · **0x2208E9E8** bare-master plaintext `.q`-style placement. TOC name keys resolve 0% from global dictionaries; naming = embedded-QB CHECKSUM_NAME pairs → bare-cut plaintext identifiers (hash-validated) → global dictionary → role names for zero-key singletons (`camera.cam`, `objects.cif`) → hex fallback. Compiled-scene payloads (skin/mdl/geom/tex) get the container's platform suffix so extraction feeds the existing converters. Extraction also writes `{stem}.cif.json`: the CIF object-binding table (resolved object/model/skeleton/anim names, skater/head flags, cross-linked to extracted `.ska`/`.skin`). `IsCut` anchors on `offset[0] == 8+16·numFiles` (exact) + ascending non-overlapping blobs within 64 bytes of padding. PS2↔Xbox pairs differ only by the GEOM↔MDL key swap. CLI: `archive <x>.cut.xbx`; routed through `unpack`. **Cutscene anim payloads convert**: `SkaFile.ParsePlatform` skips the OBJECTANIMDATA bone-name array + PARTIALANIM mask (bit24/bit19, `BonedAnim.cpp plat_read_stream`); `SkeletonFile` gates the headerless cutscene `.ske` (`12+N·44` = standalone minus its leading checksum); `SkaCommand.FindCompressTable` reaches `pre/Bits/anims` — a THUG2 SKA+SKE pair exports a validator-clean GLB. Name harvest: `QbKeyNames.CutScenes.txt` (2,032 pairs, `tools/utilities/harvest_cut_names.py`).
- **BON archives**: Dreamcast v1 (PVR textures → PNG) and Xbox v3/v4 (raw DDS extraction)
- **PAK archives**: Neversoft PAK format (THAW PS2/PC/GC, Guitar Hero era). Variable-size entry table terminated by QbKey("last") = 0xB524565F sentinel. Entry sizes: 32 bytes (compact, no filename) or 192 bytes (full, 160-byte filename field). File types identified by QbKey hash of extension (e.g. QbKey(".ska") = 0x745DCD45). Supports multiple concatenated sub-PAKs per file and companion .pab data files. **Entry data offsets are RELATIVE TO THE ENTRY'S OWN HEADER POSITION** (Queen-Bee `HeaderStart + FileOffset`), NOT absolute — fixed 2026-07-10 after shipping absolute reads that silently garbled every multi-entry pak (qb.pak, cutscene mains, cas paks; single-entry sub-PAK tables were unaffected because header position 0 makes both readings equal). Companion .pab data lives at (resolved − pak length). Validated with payload signature checks: THAW PS2 12,120 + PC 12,756 + GC 14,325 hits, zero mismatches (absolute reads fail wholesale, e.g. qb.pak.ps2 2/266 vs 266/266). Reference: Nanook/Queen-Bee PakHeaderItem.cs + PakEditor.cs (cloned at `Sample/queen-bee`). CLI: `archive <input.pak.ps2> [-o output] [-v]`. Diagnostics: `tools/diagnostics/pak_offset_check.py`. **THAW GameCube variant** (.apk.ngc + .pak.ngc, big-endian, auto-detected by sentinel byte order): same entry layout with the name QbKey at +0x0C; flag 0x80000000 marks data resident in the archive itself (header-relative offsets like LE — the earlier "hoisted tiling" model was a numerically near-equivalent approximation, now replaced); entries WITHOUT it live in the companion **.mpk.ngc** data file at RAW stored offsets (first companion entry stores 0; self-contained archives pair with a 32-byte 0xAB/0xCD stub .mpk.ngc). Generated names carry the platform suffix (.qb.ngc, .img.ngc, .ska.ngc) so extracted files route to the big-endian parsers — extracted .img.ngc decode directly via NgcTexFile (CAS graphics). 4,430 GC archives + 48 raw `*_sfx.pak.ngc` audio blobs gracefully skipped. Diagnostics: `tools/diagnostics/ngc_pak_probe.py`; QB corpus extraction: `tools/diagnostics/extract_qb_corpus.py`. **Pak entry name recovery** (60.8% named corpus-wide): the GC entry key at +0x0C = QbKey of the lowercased full path minus the last extension; dictionaries harvested proven-only from shipped debug archives (`QbKeyNames.ThawDbg.txt` 137k, `QbKeyNames.ThpgDbg.txt` 55k), GC pak+zip contents (`QbKeyNames.ThawGcPaks.txt`), cut libraries (`QbKeyNames.CutScenes.txt`), and — the biggest single source — the actual on-disk filenames across every build hashed against the unresolved keys (`QbKeyNames.DiscNames.txt`, 1,744 keys; `tools/utilities/harvest_disc_names.py`): the GC key IS the hash of the on-disk relative path, so the sibling PC/PS2 build trees spell the names the hash expects. LE entries with no key stored are keyless (offset-named, unrecoverable).
- **PS2 TEX/IMG textures**: Neversoft PS2 texture format (THPS4/THUG/THUG2/THAW). TEX files (versions 3-5): version-tagged groups, GS pixel modes (PSMCT32/16, PSMT8/4), CLUT CSM1 swizzle, Conv4to32/Conv4to16 un-swizzle. 47,154 textures across 2,485 files → PNG. THAW IMG files (version 4): single-texture format with 96-byte header, embedded GS TEX0 register at offset 0x30 (PSM, TW, TH, CPSM), GIF A+D transfer blocks, packed u16 dimensions at offset 0x48. Discriminated from THUG TEX v4 by constant 97 at offset 0x38. PSMs: PSMT4 (1248), PSMT8 (466), PSMCT16 (411), PSMCT32 (21). Layout: Header(96) + [CLUT_GIF(96) + palette + TEX_GIF(96)] + pixel_data. Non-POT textures (loadscreens, 640×448 etc.) auto-cropped from VRAM-padded dimensions. 2,146 files, 0 failures → PNG. CLI: routed via `ps2tex` command.
- **RW TXD textures**: RenderWare 3.x Texture Dictionary files (THPS3 PS2). Chunk-based container (version 0x0310), PS2-native rasters with linear pixel data (version 0). Formats: PSMT4, PSMT8, PSMCT32, PSMCT16S. 4,547 textures across 390 files → PNG. Routed automatically via `Ps2TexFile.Parse()` when first u32 = 0x0016.
- **RW DFF meshes**: RenderWare 3.x DFF (Clump) files for THPS3 PS2 .SKN files → glTF (.glb) with skeleton skinning. Standard non-native geometry format (version 0x0310): frame hierarchy, per-geometry vertices/normals/UVs/vertex colors, material list with texture references. 331 files, 330 converted (145,200 triangles), 279 textured, **304 skinned** (avg 24.2 joints), 26 rigid. Skin PLG (0x0116) parsed from Atomic Extension: PS2-specific binary layout `numBones(u32) + numVerts(u32) + boneIndices(N×4B) + boneWeights(N×16B) + bones(B×76B)`. Each bone: `id(u32) + index(u32) + flags(u32) + 4×4 f32 inverse bind matrix` (column 4 contains export-tool garbage — forced to (0,0,0,1)). Bone hierarchy reconstructed from HAnim push/pop flags (bit 0=POP, bit 1=PUSH). Joint local transforms derived from IBMs: `local = inverse(IBM_child) * IBM_parent` (row-vector convention). Z-up → Y-up rotation applied via skeleton root node. 1 file (terrorist_a.SKN) has inter-chunk padding corruption but parses gracefully (0 triangles). Texture embedding via companion `.tex` TXD files with extension-stripping name match. Shared `RwChunkReader` utilities with RW TXD parser. CLI: `rwdff <input> [-o output] [-t] [--tex path] [-v]`. GUI: integrated in Mesh Converter tab.
- **RW BSP levels**: RenderWare 3.x World (BSP) files for THPS3 PS2 level geometry → glTF (.glb). Chunk type 0x000B, version 0x0310. BSP tree structure: World → MaterialList(0x08) + PlaneSection(0x0A) binary tree → AtomicSection(0x09) leaves. AtomicSection layout: header(44B: matBase+numTris+numVerts(12B) + bbox(24B) + reserved(8B)) + positions(N×12) + normals(N×4 packed i8 if NORMALS) + colors(N×4 RGBA if PRELIT) + UV0(N×8) + UV1(N×8 if TEXTURED2) + triangles(M×8: matId:u16, v0:u16, v1:u16, v2:u16). Format flags: 0xC9 common (tristrip+prelit+modulate+textured2), 0xD9 adds normals. 33 files, 32 converted (527,407 triangles), 1 empty (Ware_Test10.bsp). Shared MaterialList with per-section matListWindowBase offset. Texture embedding via companion `.tex` TXD files. UV convention: no V-flip needed (RW TXD PNGs are top-down, matching glTF V=0-at-top). Alpha handling: OPAQUE by default; BLEND only for materials with non-zero GsAlpha (actual blending) or translucent material color (A<255). Neversoft material extension plugin (0x0294AF01) in Material Extensions carries PS2 GS ALPHA register blend mode: 0x00=opaque, 0x44=standard alpha blend, 0x48=additive (Cs*As+Cd), 0x68=additive+FIX (Cs*FIX/128+Cd), 0x42=subtractive. Additive materials get luminance-to-alpha texture conversion (dark→transparent, bright→white). Shared `RwChunkReader` utilities with RW DFF/TXD parsers. CLI: `rwbsp <input> [-o output] [-t] [--tex path] [-v]`. GUI: integrated in Mesh Converter tab.
- **COL collision meshes**: Neversoft collision files (.col.xbx, .col.wpc, .col.ps2) for THUG/THUG2/THAW → glTF (.glb). Binary format (versions 9-10): file header (32B) + per-object headers (64B each) + vertex data (fixed-point 6B or float 12B) + intensity data (1B per vert) + face data (small 8B or large 10B). Fixed-point vertices: 3×u16 (×0.0625 + bbox_min). Faces: small (flags:u16 + terrain:u16 + 3×u8 indices + pad) or large (flags:u16 + terrain:u16 + 3×u16 indices). Intensity values mapped to grayscale vertex colors. 957 files in THUG2 Xbox, 942 converted (15 empty, 0 objects), 1,343,749 total triangles, 0 glTF errors. THAW-generation files (.col.wpc) insert a 48-byte supersector block (marker u32=0 + unknown + rows + cols + scene bounds 2×4f) between the file header and the object headers — detected by the zero marker and skipped (2026-07-07; previously these parsed as 0 triangles). GameCube .col.ngc is a big-endian reordered variant whose vertex region is 0xFF-wiped on disc (engine reconstructs positions at runtime) — parseable but not standalone-convertible; see docs/backlog/formats-todo.md. Reference: io_thps_scene import_thug2.py (denetii/io_thps_scene) + NxTools fmt_thcol_import.py. CLI: `col <input> [-o output] [-v]`. GUI: integrated in Mesh Converter tab.
- **Xbox TEX/IMG textures**: Neversoft Xbox/PC texture format (THUG2). TEX (.tex.xbx): version(u32=1) + count(u32) + per-texture 32B header (checksum, w, h, levels, texel_depth, pal_depth, dxt_version, pal_size) + optional palette + per-mip data. DXT1/DXT5/paletted/raw BGRA → PNG. 18,858 textures across 990 TEX files + 2,462 IMG files, 0 failures. IMG (.img.xbx): 32B header (version=2, w, h, format, pitch, clut_size) + optional palette + pixel data. CLI: `xbxtex <input> [-o output] [-v]`.
- **GameCube SKIN/MDL meshes**: THAW GC scene files (.skin.ngc, .mdl.ngc) → glTF (.glb) with vertex colors, normals, UVs, and embedded textures — all fields big-endian. Container per THUG GC source (`Gfx/NGC/p_nx.cpp s_plat_load_scene_guts` + `p_nxsector.cpp LoadFromFile`) with a 64-byte extended sSceneHeader (THUG's 32-byte header + 32-byte THAW extension, sentinel 0xAAFFEEFF at +0x2C). Layout: header + sMaterialDL(8B)/sTextureDL(24B) tables (padded together to 32) + material/texture GX display lists + pool (VC wibbles, 32B material headers, UV wibbles, 32B pass headers, pos f32×3, col RGBA8, tex s16×2, nrm s16×3) + per-object [64B sObjectHeader + skin lists + per-mesh 64B sDLHeader + geometry GX display list] + hierarchy (80B CHierarchyObject entries) + CAS footer. **Geometry = real GX display lists**: CP loads set VCD_LO/VCD_HI (pos/nrm idx16, clr0 idx8/16, 0-3 UV sets idx16), draw ops 0x80-0xA0 carry indexed vertex tuples; VAT7 formats from `Sys/ngc/p_hwinit.cpp`. Scales: skin positions s16**/32** (THAW halved THUG's 1.9.6 shift to double the range), normals s16/16384, UVs s16 (u=a/1024, v=1−b/1024), weights s16/16384. Skin lists per `NX/mesh.cpp` ApplyMeshScaling + `NX/instance.cpp`: singles {n, mtx, n×6s16}, doubles {n, bone0|bone1<<8, n×6s16, n×2s16 weights}, adds accumulate a third bone onto existing verts by index. **Material passes reference textures by INDEX into the companion .tex.ngc dictionary** (record order; parser stores index+1 in TextureChecksum; sTextureDL.tex_offset[0] ≥ 0 gates textured). No skeleton files ship on GC (bones pre-baked, static export like THAW PS2). Validated against PC/PS2 Rosetta pairs: pigeon positions/triangles exact vs .skin.wpc (46 verts/45 tris both), ped_baller UVs/normals match the PS2 decode (912-hit UV variant test, 644/656 normals). **722/722 files (588 .skin.ngc + 134 .mdl.ngc), 427,343 triangles, 0 failures, 0 validator errors.** Parser: `Core/Formats/Mesh/XbxScene/NgcSceneFile.cs` (produces XbxScene, shares the Xbox glTF writer). CLI: routed via `mesh`. Diagnostics: `tools/diagnostics/ngc_scene_probe.py`.
- **GameCube TEX/IMG textures**: THAW GC texture format (.tex.ngc dictionaries, .img.ngc single images) — all fields big-endian. Dictionary: header (u8 version=1, u8, u16 count, u32 tableOffset=8) + count×32-byte record table + data region; records carry absolute dataOffset/alphaOffset. Formats: GX_TF_CMPR (0x0E — 8×8 tiles of four DXT1 blocks, BE RGB565, MSB-first indices; DXT5-equivalent alpha ships as a second CMPR chain whose green channel is the alpha, per THUG GC texture.cpp) RGBA8 (4×4 tiles as AR/GB 32-byte planes; real height = colorSize/(4×width)), and C8 (8×4 tiles of palette indices + trailing 256-entry big-endian RGB5A3 palette — CAS icons/banners). Format byte 0x06 covers BOTH RGBA8 and C8; they are distinguished arithmetically (C8 iff colorSize == width×rows + 512 with rows ≤ POT height). Images stored bottom-up (y-flipped on decode). Layout established via PC↔GC Rosetta pairs (pixel-exact vs .tex.wpc decodes). 3,369/3,369 files (722 .tex.ngc + 2,647 .img.ngc), 4,630+ textures, 0 failures. Parser: `Core/Formats/Texture/Ngc/NgcTexFile.cs`. CLI: routed via `xbxtex`.
- **Xbox MDL/SKIN/SCN meshes**: Native Xbox/PC scene files (.skin.xbx, .mdl.xbx, .scn.xbx, .skin.wpc, .mdl.wpc, .scn.wpc) from THUG2 + THAW → glTF (.glb) with vertex colors, normals, UV coordinates, and material references. **THUG2 format**: Version triple (1,1,1), sequential multi-pass materials, degenerate triangle strip index buffers. 925 files (751 SKIN + 174 MDL), 502,851 triangles, 0 failures. .scn.xbx level scenes (192 files across THUG2 Xbox + Windows builds, 3,005,651 triangles, 0 validator errors) use the same format and parser — the extension is routed since 2026-07-07. **THAW format**: 32-byte file header (no version triple), 0xBABEFACE magic sentinel, parallel material pass arrays (4 passes), CScene object with relative offsets, 0x7FFF triangle strip separators (pre-triangulated). 723 files (589 SKIN + 134 MDL), 428,925 triangles, 0 failures, 0 glTF errors. Shared vertex format (stride-based interleaved, packed 11+11+10 skinning weights). Format detection: `ThawSceneFile.IsThawScene()` (pre_material_header_size=16 at offset 0x21) vs `XbxSceneFile.IsXbxScene()` (version triple 1,1,1). Hierarchy links in MDL files for multi-part objects. Format reference: nxtools fmt_thscene_import.py (THUG2 base) + fmt_thawscene_import.py (THAW) + THUG source material.cpp. CLI: `xbxscene <input> [-o output] [-t] [--tex path] [-v]`.
- **Cross-platform skeleton (.ske)**: Neversoft cross-platform skeleton format (THPS4/THUG/THUG2). Two sub-formats: THPS4 (checksum + numBones + 3 name tables, no neutral poses, size = 8 + N×12) and THUG/THUG2 (checksum + version + flags + numBones + names + neutral poses, size = 16 + N×44). 154 files across 3 games (34 THPS4, 62 THUG, 58 THUG2). Auto-discovered for .skin.ps2 files via CompanionSearch. THPS4 .ske files are the ONLY skeleton format available (no .ske.ps2), enabling bone hierarchy export for all 34 THPS4 skinned meshes. THUG/THUG2 .ske files provide cross-platform alternative to .ske.ps2.
- **THAW skeletons + animations (.ske/.ske.ngc, .ska/.ska.ngc)**: THAW-generation animation family for PS2/PC (little-endian) + GameCube (big-endian) — the GC files are field-for-field endian mirrors, parsed by one endian-parameterized path (`Core/BinaryIO/EndianSpanReader`). Shipped 2026-07-10. **THAW SKE** (`ThawSkeletonFile`, 973/973 files: 348 PS2 + 330 GC + 295 PC): u16 version=1 + u16 headerSize=0x30 + u32 numBones + 6×u32 offset table + u32 matrixOffset + u32 vecOffset(0x30); body = vec4[N] local translations (w = local quat W) + mat4[N] **precomputed inverse bind matrices** (row-vector, unlike THUG which computes them at load) + bone/parent/flip QbKey arrays + u32[N] flags (all 0) + constant 128-byte 0x7F7FC99E block. Locals derived as inverse(IBM_bone)×IBM_parent (verified exact vs the stored vec4s). Detection gate is exact and dispatches FIRST in `SkeletonFile.Parse`; reports Version=2 (has bind poses). **THAW SKA v0x28** (`SkaFile.ThawParser`, ~21,350/21,350 across THAW×3; P8 + THPG verified grammar-compatible): version-gated before the THUG flag dispatch. Header: ver 0x28 + flags + f32 duration + u8 pad/u8 numBones + u16 numQ/numT/numCustom + 20-byte bone mask (all-0xFF in corpus). Compressed family (bit23, 91%): u32 qBytes/tBytes @0x28 + per-bone u16 size tables + raw-LE key blobs (blobs and standardkey tables are LITTLE-ENDIAN even on GC, like QB script bodies; only header/tables/preludes mirror). Key grammar = THUG BonedAnim + THAW deltas verified against the THAW PS2 ELF readers (`tools/ghidra/thaw-ps2/run_phase_ska_key_readers.sh`): bit16 (always set) = byte-width components index the scalar column (4th s16) of standardkeyQ entries; bit15 = compact keys (all components 1 byte; width-clear = byte<<8); bit8 = leading u16 15-bit timestamp per Q key; bit19 = u32 origBones + u32 masks between size tables and blobs. Hi-res family (bit28, cutscene camera/object masters): 0x28-byte header + bit24 bone-name QbKeys + u8 count pairs (u16 when bit22) + 16-byte keys (u16 ts:15+sign + 3×f32, endian-mirrored on GC); custom keys (35 files) not consumed. **Flags bits 14+17 = additive translations** (deltas over neutral pose, vadd in the ELF evaluator) — honored by `SkaPoseEvaluator` and the glTF channel baker. Skeleton-less camera masters export as flat rigs with QbKey-named nodes (`ska <file>` → node-TRS GLB). Pairing/validation: PS2↔GC by pak entry order (GC names = QbKey hashes, PS2/PC = pak offsets — no filename correspondence); the cutscene "descriptor .ska" once hypothesized does not exist (that data is `<name>_cam_pak_info.qb`, already parsed). Diagnostics: `tools/diagnostics/thaw_anim_pairs.py`, `thaw_ske_probe.py`, `thaw_ska_probe.py`, `ska_version_census.py`. CLI: `ska` (suffix `.ska.ngc` routed; `--ske` accepts `.ske.ngc`).
- **PS2 MDL/SKIN meshes**: Native PS2 scene files (.mdl.ps2, .skin.ps2, .iskin.ps2) → glTF (.glb) with vertex colors, normals, UV coordinates, and material references. Version triples: THPS4 (3,4,1), THUG (5,6,1), THUG2 (6,6,1). 2,299 standard files across 3 games (574 THPS4, 812 THUG, 913 THUG2). THPS4 uses full float-precision vertices (40B non-skinned, 64B skinned). THUG/THUG2 non-skinned uses floats with packed sint16 normals (32B); skinned uses packed sint16 for positions/UVs/normals (28B). Triangle strips encoded via ADC bits per-vertex (0x8000 = strip restart). Packed normals: 2×sint16, nz=sqrt(1-nx²-ny²), Z sign from LSB of nx. Skinned position scale: SUB_INCH_PRECISION=16.0 (÷16). Skinned UV scale: ÷4096. Materials are single-pass (not multi-pass like cross-platform format). VC wibble has phase field in ALL versions (THUG source bug omits it). THUG2 shader_id is always 4 bytes (no conditional specular color). 739 THUG2 .skin.ps2 files with version (1,N,M) are pre-compiled VIF/DMA rendering chains (bones pre-baked, lighting pre-computed, UVs confirmed via numerical cross-reference); detected and gracefully skipped since matching .iskin.ps2 files provide higher-quality data. Reference: THUG source (scene.cpp/mesh.cpp/material.cpp), validated via `tools/diagnostics/ps2_scene_trace.py`.
- **THAW PS2 .skin.ps2 meshes**: Pre-compiled VIF/DMA rendering chains for THAW PS2 (.skin.ps2) → glTF (.glb). Binary layout: 32B header (numObjects, totalMeshes1, totalMeshes2, dataSize, bsphere) + object table (8B×N: checksum+meshCount) + entry table (64B×M: materialChecksum, textureChecksum, gsAlpha, ownerObjectChecksum) + variable-length gap chunks + DMA/VIF rendering data. FLUSH+DIRECT VIF opcode pairs mark material/setup changes inside the chain (full dword validation: 0x10000000 or 0x11000000 to filter false positives from gap chunk data), not true mesh starts; the VIF preamble before the first FLUSH+DIRECT can contain real vertex batches for the first material and must be included. Per-setup VIF batches: STCYCL(CL=3,WL=1) interleaved mode with V3_16 positions (sint16/16.0), V3_8 normals (sint8/127.0), V4_16 (c0=U sint16/4096, c1=V sint16/4096, c2=bone_hi|output_addr, c3=duplicate_addr|bone_data). **Strip topology via c2[7:0] + c3[7:0] output buffer addresses**: Each vertex's c2[7:0] encodes its primary position in the VU1 GIF output buffer (decreasing by 3 per slot). c3[7:0] encodes a duplicate output position; when c3[7:0] != c2[7:0], the VU1 microprogram writes the vertex to BOTH positions, filling gap slots that would otherwise fragment the strip. Sorting all entries by output address descending reconstructs the output strip order. Gaps (diff != 3) indicate degenerate vertex insertions → sub-strip boundaries. Cross-reference against PC ground truth on `skater_lasek` improved to 83.4% precision, 70.6% recall, F1=76.5% after including preamble batches; the remaining misses are mostly cases where all PS2 vertices exist but the strip topology differs across c2 runs or batches. Adaptive per-batch edge-length filter removes cross-body artifacts (median max-edge² × 16 threshold, marks oversized triangles as strip restarts). 332/332 files, 209,368 triangles, 0 parse failures, 0 glTF errors. No .geom.ps2 files exist for THAW. Also handles THUG2 pre-compiled .skin.ps2 without .iskin.ps2 companions. CLI: routed via `ps2scene` command. Diagnostics: `tools/diagnostics/thaw_ps2_vif_walk.py`, `tools/diagnostics/thaw_ps2_strip_decode.py`.
- **PS2 GEOM meshes**: Pre-compiled CGeomNode rendering trees (.geom.ps2) → glTF (.glb). VIF opcode parser extracts vertex data from embedded DMA chains. 1,800 files across 3 games (603 THPS4, 933 THUG, 264 THUG2), 1,798 converted (2 empty fireball.geom.ps2 particle placeholders). Texture embedding: THUG/THUG2 use CGeomNode.texture_checksum at +0x44 directly (932/933 THUG, 263/264 THUG2 textured). **THPS4 texture resolution via VRAM simulation**: CGeomNode.texture_checksum=0 for ALL THPS4 leaves; textures identified by GS TEX0_1 register values in DMA chain VU1 input (UNPACK V4_32 GIF tag + UNPACK V3_32 register writes). TEX0 contains TBP (VRAM texture base pointer) and CBP (CLUT base pointer). `Ps2VramAllocator` simulates PS2 GS VRAM allocation from TEX files (replicating texture.cpp LoadTextureGroup) to build (TBP,CBP)→checksum mapping. 602/603 THPS4 files textured (7,931 textures embedded, 4,727 VRAM mapping entries). Validated via `tools/diagnostics/ps2_geom_trace.py`, `tools/diagnostics/ps2_geom_gscontext.py`, `tools/diagnostics/ps2_vram_sim.py`.
- **Audio**: XA (PS1 ADPCM), VAB (PS1 sound banks), VAG (PS2 SPU-ADPCM, headered + headerless), PSS (headerless SPU-ADPCM, same as VAG), ADX (CRI Middleware), KAT (Dreamcast soundbanks), SFX (cue banks with companion KAT/VAB resolution) → WAV. SFX cue format decomp-verified (THPS2 PSX proto `SFX_ParseSFXFile`/`playSFX`): flat 16-byte records from offset 0, 0xFFFFFFFF-terminated — marker(u8, 0xFE=loop), VAB program(u8), category(u8, selects tone 1<<cat), MIDI note(u8), pitch(u16), volume(u16), alias(u16, the cue's lookup key). VAB companions resolve cues exactly via the program tone table (toneAttr = vab + program×0x200 + 0x820 + category×0x20, VAG index at tone+0x16) with cue-note-adjusted sample rates; Spider-Man-style KAT/PC banks use the direct program→sample rule; THPS2 DC KAT banks (whose tone tables shipped only in the PSX VAB) fall back to full companion-bank extraction. 386 sample banks parse clean, 7,571/7,968 VAB cues resolve exactly (the rest reference undefined programs = silent at runtime). Diagnostics: `tools/diagnostics/sfx_cue_probe.py`. **Audio preview** (GUI): in-tab playback with play/pause/stop, seekable slider, position display, and temp file caching. Converts selected file/sample to WAV via MediaPlayer API. Supports ADX/XA/VAG/PSS (whole file) and VAB/KAT/SFX (individual samples or resolved bank samples).
- **DDM meshes**: Xbox 3D level geometry → glTF (.glb) with materials, vertex colors, texture references, and .lit lights. DDM vertices are in local/object space. Level assembly uses PSX layout files for world-space placement: each PSX object entry provides a 20.12 fixed-point position (raw/4096 → float), matched to DDM objects via CRC-32 hash lookup. Coordinate mapping confirmed via THPS2X Xbox decompilation: `world_pos = psx_int32 / 4096`, no axis negation; glTF output uses `(-X, -Y, +Z)` matching vertex conversion. Level DDMs produce three .glb files: `{name}_level.glb`, `{name}_objects.glb`, `{name}.glb` (combined). Standalone DDMs (no PSX companion) produce one .glb file.
- **TRG triggers**: Level trigger/script files → JSON — spawn points, camera paths, rail networks, enemy spawns, command lists, bytecode scripts. Versions 2.0 (Apocalypse/THPS) and 2.1 (Spider-Man). CLI: `trg <input> [-o output] [-v]`. GUI: integrated in Script Decompiler tab.
- **QB compiled scripts**: Neversoft compiled game scripts (`.q` source → `qcomp` → `.qb` binary) → decompiled source text (`.q`). Two generations, both routed transparently through `QbFile.Parse`. **THPS3-THUG2 (2001-2004)**: raw token stream (69 token types, no magic number/header). Two-pass parsing: pass 1 collects CHECKSUM_NAME pairs, pass 2 indexes top-level items (scripts: KEYWORD_SCRIPT...KEYWORD_ENDSCRIPT, globals: NAME EQUALS value ENDOFLINE). 2,361 files across 6 builds, 0 parse failures, 36,634 scripts, 1,241,153 globals, ~77% name resolution. Format reference: THUG source `Gel/Scripting/tokens.h` (token enum), `skiptoken.cpp` (token sizes), `parse.cpp` (ParseQB). **THAW sectioned QB (2005, `.qb.ps2`/`.qb.wpc`/`.qb.ngc` + `.sqb.*`, same family as Guitar Hero)**: 28-byte header (u32 0 + u32 fileSize + fixed 20-byte signature) + typed sections holding a value tree (int/float/string/pair/vector/QbKey/struct/array). Two info-value encodings for identical layouts: OLD (PS2/PC LE, e.g. section 0x000C0400, struct item 0x00000300) and NEW (GC BE, e.g. 0x00200C00 / 0x00810000 — Queen-Bee's "Wii" column); auto-detected per file. Scripts are LZSS-compressed blobs (same `LzssDecoder` as PRE v3) of the classic token stream — **always little-endian, even on GC** — extended with THAW-only tokens: 0x47 fast-if / 0x48 fast-else / 0x49 fast-case (u16 runtime skip operands; explicit endif tokens remain) and 0x4A inline struct (u16 LE length + pad-to-4 + serialized struct in FILE byte order with relative pointers). Struct items add a THAW-only inline-script type (info 0x0087SSSS new / 0xSSSS0F00 old, SSSS = raw script byte size). `QbSectionParser` synthesizes the equivalent raw token stream so the existing indexer/decompiler/GUI work unchanged. Sweep: **11,909/11,909 files (2,933 PS2 + 3,754 PC + 5,222 GC), 49,755 scripts + 37,658 globals, 0 failures.** THAW name resolution: **97.1% PS2 / 99.2% PC / 89.1% GC** via `QbKeyNames.ThawDbg.txt` — 137,054 checksum→name pairs harvested from the `[Checksums]` sections of the shipped debug archives (`DATAP/pak/dbg.pak.ps2` + PC `dbg.pak.wpc`) by `tools/utilities/harvest_thaw_dbg_names.py`. Reference: Nanook/Queen-Bee `QueenBeeParser/Qb` (`Sample/queen-bee`); diagnostics: `tools/diagnostics/thaw_qb_probe.py`. Name resolution: 3-tier (file-local CHECKSUM_NAME → global QbKey dictionary (~154,700 entries across the `QbKeyNames*.txt` embedded resources) → `#"0xHHHHHHHH"` fallback). Decompiler reconstructs indentation for script/endscript, if/else/endif, begin/repeat, switch/case/endswitch, struct/array nesting. CLI: `qb <input> [-o output] [-v]`. GUI: integrated in Script Decompiler tab.
- **SFD video**: CRI Sofdec video (Dreamcast) → MP4 via ffmpeg. MPEG-PS container with MPEG-1 video + ADX audio. Requires ffmpeg on PATH.
- **STR video**: PS1 MDEC video streams → MP4 via pure C# decoder + ffmpeg encoding. 2336-byte CD-ROM sectors with interleaved XA-ADPCM audio. Variable resolutions (320×240, 320×192, 96×64). Present in Apocalypse, Spider-Man, THPS1/2 (PS1). Audio extracted via XaDecoder, raw RGB24 frames piped to ffmpeg stdin.
- **Video tab** (GUI): Unified Video Conversion tab handles both SFD and STR files with full playback preview via MediaPlayerElement.
- **Unpack tab** (GUI + CLI): Recursive extraction of all game archives in a directory. Multi-pass loop: scans for archives → extracts → rescans for nested archives (e.g. WAD containing PRE) → repeats until no new archives found. Supports WAD, PRE, compressed PRE (PRE3/PRX/PRD/PRF/PRG), PKR, DDX, BON, PAK, QTex ZIP, CUT. Already-extracted detection (skips if `{stem}/` directory exists and is non-empty). GUI: folder picker, archive list with status/progress, cancel support. CLI: `unpack <input-dir> [-v]`.

## glTF Validation

After converting meshes to .glb, **always validate the output** using the Khronos glTF validator. Download a release from <https://github.com/KhronosGroup/glTF-Validator/releases> and either drop the binary at `tools/gltf_validator_bin/gltf_validator.exe` (kept out of the repo via `.gitignore`) or invoke it from wherever it lives on your system.

```bash
# Validate a single file
tools/gltf_validator_bin/gltf_validator.exe <file.glb>

# Validate a directory (recursive)
tools/gltf_validator_bin/gltf_validator.exe <directory>

# JSON report to stdout (parse with Python for material/texture/mesh counts)
tools/gltf_validator_bin/gltf_validator.exe -o <file.glb>
```

Key things to check: 0 errors, 0 warnings. `UNUSED_OBJECT` infos on `TEXCOORD_0` indicate meshes with UV coordinates but no texture assigned to the material — expected for untextured geometry, but a bug if textures should be present.

For quick programmatic checks, parse the GLB JSON directly (first chunk after 12-byte header):
```python
import struct, json
with open('file.glb', 'rb') as f:
    f.read(12)  # skip magic/version/length
    clen, _ = struct.unpack('<II', f.read(8))
    d = json.loads(f.read(clen).decode().rstrip('\x00'))
    print(f"Materials: {len(d.get('materials',[]))}, Textures: {len(d.get('textures',[]))}")
```

## Deferred Items

### Not Game Formats / Not Archives

- **SCC**: Microsoft Visual SourceSafe `vssver.scc` version tracking files. Development artifacts accidentally shipped on disc. No game data.
- **BIN**: Generic file extension used for PS1 MIPS code overlays (game logic, menu screens), THPS2 data tables (cretex.bin, tricks.bin), and Dreamcast bootstrap executables. ~89% compiled machine code. Not suitable for asset extraction. See [spidey-decomp](https://github.com/krystalgamer/spidey-decomp) for Spider-Man module decompilation.
- **PAK raw data files**: 987 of 1,732 `.pak.ps2` files in THAW are raw data without entry tables (not extractable archives). Detected and gracefully skipped by `PakArchive.IsPakArchive()`.
- **PRK**: Custom park save data (8-20KB files named `custom1-20.prk`). Not archives.

### Unsupported Game Asset Formats (Hardest → Easiest)

- **PPV**: Spider-Man PSX prototype runtime container (`BVmC` magic). 14 files under `WTC/SOUNDS` in `Spider-Man (2000-2-4, PSX - Prototype)`. Appears to be a real runtime media container rather than a tooling artifact. Treat as audio-first research until proven otherwise. No solid in-repo or open-source parser reference yet.
- **VID**: THAW GameCube movie container (`VID1` + `FRAM`/`VIDH`/`AUDH`/`AUDD` chunks). 8 files under `movies/vid` in `Tony Hawk's American Wasteland (2005-8-22, GC - Final)`. Bundled THUG source documents the container and audio path, but video decode still depends on external decoder APIs.

### In Progress (Not Yet Bug-Free)

- **Script Decompiler tab** (GUI): Unified tab (`App/Tabs/ScriptDecompilerTab.xaml`) handles both TRG trigger files and QB compiled scripts. TRG: file picker (.trg), node tree with type/position/command detail panels, JSON export. QB: file picker (.qb), item tree (SCRIPT/GLOBAL) with decompiled source detail panel, `.q` source text export. Directory scan finds both extensions with background parsing for metadata. Shared expandable list UI via `{Binding}` templates (supports polymorphic TrgFileEntry/QbFileEntry + TrgNodeEntry/QbItemEntry models).
- **QBKey name resolution**: all `QbKeyNames*.txt` embedded resources (~424,800 hash→name mappings total) are loaded at startup into a `FrozenDictionary` (first-wins, main file has priority). Format: `name=0xHASH` per line. `QbKeyNames.txt` (18,523): discovered via `qbkey cross-ref` matching DDM plaintext names against PSX QBKey hashes across 104 THPS2X Xbox file pairs, plus archive filename scanning — coverage: **mesh hashes 81.9% (19,336/23,611)**. `QbKeyNames.ThawDbg.txt` (137,054): harvested from THAW's shipped debug archives (`dbg.pak.ps2`/`dbg.pak.wpc` `[Checksums]` sections) via `tools/utilities/harvest_thaw_dbg_names.py` — drives THAW script decompilation to 89-99% resolution. **`QbKeyNames.QbLocalNames.txt` (206,215) is the biggest single source**: inline `CHECKSUM_NAME` (token 0x2B) registrations harvested GLOBALLY from the THPS3/THPS4/THUG/THUG2 script corpus and validated by re-hash (`tools/utilities/harvest_qb_localnames.py`; census `tools/diagnostics/qb_localname_census.py`). The engine only ever used these file-locally (`QbFile.LocalNames`), so a name defined in one script did not resolve in another; aggregating the proven pairs gives those four games — which ship NO debug archives, unlike THAW/Project 8 — their primary cross-file resolution. THAW's own `CHECKSUM_NAME` pairs were stripped in retail (they don't re-hash), which is exactly why THAW needs the separate `dbg.pak`. `DiscNames`/`ScriptRefs`/`CutScenes`/`ThpgDbg` add proven pak-key/script-ref/cutscene/Project-8 names. Texture identifiers are build-tool-assigned IDs (not name hashes), so QbKey resolution does not apply to them — but THAW textures DO recover source-art names via a **separate** map, `Core/Formats/Texture/ThawTextureNames.cs` (+ `.txt`, 2,132 pairs): the compiled-texture checksum → original art name mined from the `debug.log` inside each QTex `.tex.zip` bundle (`tools/utilities/harvest_thaw_texture_names.py`). It is deliberately kept OUT of `QbKeyNames*.txt` — those checksums are opaque build ids, not CRC(name), so mixing them in would poison every proven-name harvest's `existing_hashes()` and the coverage metric. Consumed by `ThawTexFile`/`NgcTexFile` naming (`ThawTextureNames.TryResolve(checksum) ?? QbKey.TryResolve(checksum)`).
  - **Hash algorithm**: PS1/DC/Xbox-era Neversoft games use **case-sensitive** reflected CRC-32 (polynomial 0xEDB88320, init 0xFFFFFFFF, no final XOR, **no lowercasing**). This was confirmed by verifying DDM checksum fields match case-sensitive CRC-32 of mixed-case mesh names (e.g. `Itm_Bonus01`). `QbKey.Hash()` is case-sensitive; `QbKey.HashLower()` provides the THUG+ era lowercase variant. The `io_thps_scene` Blender addon documents the same split: `crc32b_from_string()` (no lowercase) for THPS1/2 vs `crc_from_string()` (lowercase) for THUG+.
  - **Texture identifiers (NOT name hashes)**: The PSX "texture name" array stores opaque identifiers used as keys in `TextureChecksumHashTable` (a 512-bucket hash table, decompiled from THPS2 proto). `ProcessNewPSX` reads each identifier, looks it up via `Spool_FindTextureEntry__FUi`, then **replaces the value in-place with a pointer** to the texture entry struct. Values include small numbers like `0x0000001E` (30) that cannot be CRC-32 of any string, ruling out name hashing. Same identifier appears across files with different texture dimensions (e.g. `0x3FB86DC4`: hawk2.PSX 32x64 vs hawk2b.PSX 32x32), proving they're not pixel-data checksums either. The `TexId` field in the per-texture header is actually a **palette hash** (passed to `Pal_FindPaletteEntry__FUi`), not a texture name. These are build-tool-assigned identifiers; name resolution is not applicable. See `tools/ghidra/thps2-psx-proto/output/psx_decompiled.c` for full decompilation.

  - **Texture hash diagnostic**: `tools/utilities/texture_diagnostic.py` — Python diagnostic script for analyzing PSX texture/mesh hash populations and testing alternative hash algorithms.   - **GHIDRA decompilation pipeline** (`tools/ghidra/thps2-psx-proto/`): Decompiles PSX functions from THPS2 PSX Prototype (SLUS_900.86 + MAIN.SYM, 3,566 PSY-Q symbols). `ImportSymHeadless.java` (pre-script: reads SYM directly, imports 8,652 struct definitions, 2,759 typedefs, 3,568 typed globals, 1,611 function signatures; loads PSY-Q 4.60 SDK GDT; sets GP=0x800D7CA0), `DecompilePsxFunctions.java` (post-script: decompiles 41 targeted functions by address), `run_decompile.sh` (driver). - **THAW .tex.ps2 scene texture metadata**: Scene texture metadata files (NOT the same format as THUG TEX). Header contains model checksum + per-texture entries with GS register values (TEX0, MIPTBP), dimensions, and texture checksums. 328 files, each a companion to the same-named `.skin.ps2`. Internal texture checksums are NOT QbKey hashes. (The PC `.tex.wpc`/`.img.wpc` 0xABADD00D DXT containers ARE implemented — `ThawTexFile`/`ThawImgFile` via `xbxtex`; verified 2026-07-07 at 3,203/3,203 files, 4,472 textures.)
- **RW DFF / THPS3 animations**: No animation support yet. THPS3 likely uses RenderWare animation chunks or custom Neversoft formats. THPS4+ uses Neversoft SKA format (BonedAnim.cpp). Skinned DFF models currently export in bind pose (T-pose).

### Research & Improvements

- **PowerVR format improvements**: DDS output with mip level preservation is implemented for formats 0x200 (twiddled+mip) and 0x400 (VQ+mip). Mip atlas PNG (`_mips.png`) output renders all mip levels into a single image for visual verification. GIMP PVR research: `Sample/gimp/plug-ins/common/file-pvr.c` supports additional format types (Small VQ, CLUT4/8, stride, etc.) but none of these appear in any Neversoft game files — scan of 20,726 textures across 1,041 files found zero unsupported format codes. Current six format types (0x100, 0x200, 0x300, 0x400, 0x900, 0xD00) provide complete coverage.
- **PSX mesh conversion**: Parser (`Core/Formats/Mesh/Psx/PsxMeshFile.cs`), glTF writer (`PsxGltfWriter.cs`), CLI (`CLI/PsxMeshCommand.cs`), and GUI tab (`App/Tabs/MeshConverterTab.xaml`). Level geometry (`_g.psx`) AND character models both work — re-verified 2026-07-07 with a five-build sweep (Apocalypse/THPS1/THPS2/Spider-Man/SM2EE): 490 character-class files converted with **zero real failures** (the only non-conversions are texture-only costume files correctly reporting "No mesh data"); Bruce (Apocalypse), Burnquist (THPS1), Hawk (THPS2), and Spidey render correct textured characters. The earlier "garbled character geometry" note predated the PSX animation-era mesh fixes and is obsolete. Remaining PS1-era gaps are animation-side (see `memory/psx_anim_status.md`), not static meshes. NxTools' `psx/import_psx.py` remains a useful cross-reference (skinned ÷16 scaling, HIER hierarchy, face stitching).
- **THPS2 PSX matching decompilation** (`tools/ghidra/thps2-psx-proto/`): **Full matching decomp project** — goal is 1:1 binary reproduction, not just a format reference. 682/1455 perfect matches across 67 TUs. Compiler: GCC 2.91.66-psx (EGCS 1.1.2), flags: `-O2 -fno-strength-reduce -G8 -msoft-float -mno-abicalls`. Build/match scripts: `wmatch.sh`, `match_combined.sh`, `match_all.sh`. See `MATCHING_REFERENCE.md` for per-function ceiling analysis, C-source techniques, and per-TU completion status. Ghidra reference decompilation: 41 functions with full type-aware output (`output/psx_decompiled.c`).
